==================
InfoHub 网页采集
==================

为没有 RSS 的站点提供采集能力。核心机制是**把爬虫做成配置而不是代码**。

接入一个新站点 = 加一条记录
===========================

结构常规的站点：新建一条 ``infohub.web.profile``，填好条目链接选择器与几个字段
选择器，再建一个 ``transport = web`` 的源指向它。**不写一行 Python。**

只有需要 JS 渲染、登录、反爬对抗的站点才需要写渠道模块。这是"扩展性主要来自数据，
模块数随来源数次线性增长"（ADR-018 / N10）在网页来源上的落点——否则每个博客一个模块，
模块数会线性爆炸。

模块自带三份示例配置（通用语义化博客、WordPress 默认模板、列表页自带全文），它们
没有对应任何代码，纯数据，可以直接用或复制后改。

两阶段抓取
==========

1. **列表页** —— 按分页方式翻页，用 CSS 选择器取出条目链接
2. **详情页** —— 逐个抓取并用选择器提取字段

分页支持三种方式：不分页、页码参数（``{page}`` 占位符）、下一页链接。

``detail_mode = list_only`` 适用于列表页本身就带全文的站点，跳过第二阶段，把请求数
从 N+1 降到 1。此时字段选择器作用在**列表项片段**（最近的 ``article`` 或 ``li``
容器）上，而不是详情页。

只抓新的（关键的成本控制）
--------------------------

翻完列表页后，先把**已入库的链接剔除**，再去抓详情页。没有这一步，每轮都会把所有
详情页重抓一遍——这是网页采集与 RSS 最大的成本差异：RSS 一次请求拿到全部条目，
网页采集是每条一次请求。

比对用 ``external_id``（mapper 把 URL 作为 external_id），一次查询解决。测试里有
专门的断言：第二轮完全不抓详情页；列表页新增一条时只抓那一条。

为什么用 CSS 选择器
===================

用 BeautifulSoup + soupsieve，两个库容器都已自带。CSS 选择器对配置作者比 XPath 友好
得多。（``cssselect`` 未安装，所以 ``lxml.cssselect`` 不可用；bs4 的 ``select()``
底层就是 soupsieve。）

选择器在**保存时**就用 soupsieve 编译校验，坏选择器不会跑到采集流水线里才炸——与
``infohub_filter`` 对正则的处理同一个原则。

安全
====

* 所有出网都走核心的 ``infohub.http``，因此每个 URL 都过 SSRF 校验。**这在网页采集里
  格外重要**：详情页链接来自被抓取的页面，是外部可影响的输入，站点被攻破或页面被注入
  就可能出现指向内网的链接。
* ``same_host_only`` 默认开启，把跟随范围限制在同域。
* 正文经 ``html_sanitize``；提字段前先删 ``<script>`` / ``<style>`` 与配置的噪声节点
  ——顺序很重要，否则广告位里的 ``<h1>`` 可能被当成标题（测试里有这一项）。
* 详情页之间按源上的 ``min_request_interval`` 休眠。

``render_js`` 是预留字段，尚未实现
==================================

勾选后采集**直接报错**，而不是静默抓到一个未渲染的空壳页面。这类站点目前需要另写
渠道模块。将来若实现，`.playwright-mcp/` 说明环境里已有 playwright 可用。

固有的维护成本
==============

选择器会随站点改版失效，这是网页采集与 RSS 的本质差别。缓解手段：

* 每条配置的「备注」里写清结构假设，便于日后复查
* 抓不到条目时列表页翻页会提前终止（不会空转），抓取日志里 ``item_found`` 为 0 就是
  失效信号——建议对这类源配一条告警

依赖
====

``beautifulsoup4``、``soupsieve``、``lxml``、``python-dateutil``，容器镜像全部自带。

注意 ``external_dependencies`` 里要写 **PyPI 包名**而不是 import 名：写 ``dateutil``
会让 Odoo 报"不是有效的 PyPI 包名"（它优先用 ``importlib.metadata.version()`` 查）。

测试
====

见 ``.kiro/specs/infohub/stage6_test.py``（56 项）：选择器保存期校验、三种分页、
两阶段抓取与字段提取、只抓新链接、同域限制、噪声剔除顺序、``list_only`` 模式、
``render_js`` 报错、与论文介质组合的 DOI 收敛、**零代码接入验收**。
