# 业务需求（requirements）

## 背景

公司使用企业微信自建应用向员工推送通知（公告、简报等）。需要一个 Odoo 侧的管理入口：
配置应用凭证、缓存通讯录、以可视化方式发布应用消息，并保留完整发布历史用于审计与排查。

## 功能需求

### R1 企微应用配置

- 维护自建应用的 CorpId / AgentId / Secret，按公司隔离（多公司各配各的应用）。
- access_token 自动获取、缓存到应用记录上并自动刷新，跨请求/跨 worker 复用。

### R2 通讯录缓存

- 从企业微信拉取部门、成员，缓存为本地 `wecom.department` / `wecom.user`，
  供发布消息时选择接收人。
- JS-SDK 域名校验文件的存放（供 H5 页面 JS-SDK 鉴权用）。

### R3 应用消息发布

- 三种消息类型：文本卡片 `textcard`、图文 `news`、图文素材 `mpnews`（HTML 正文）。
- 接收范围：成员 / 部门 / 标签 / 全员（@all），可混合。
- 图文超过 8 篇自动分批发送（企业微信单次上限 8 篇）。
- mpnews 封面图与正文图片自动上传素材，正文图片 URL 自动回填。
- 界面按钮发布；其他模块通过统一对外接口 `wecom.app.send_message()` 发布（自动留历史）。

### R4 发布历史

- 每次发送落一条 `wecom.app.message` 记录：内容、接收范围、发送时间、
  无效接收人（invaliduser/party/tag）、错误信息。
- 状态机：草稿 → 已发送 / 发送失败。

### R5 消息撤回（本次新增）

- 发送成功后把企业微信返回的 `msgid` 记录到发布历史上（多批发送记录全部 msgid）。
- 24 小时内可从界面一键撤回：企业微信会在接收人客户端删除该消息。
- 撤回结果回写：成功 → 状态"已撤回"+ 撤回时间；失败 → 错误写入发送结果，状态不变。

## 边界（明确不做）

- 不做企业微信 OAuth 网页登录 / JS-SDK 签名下发（只存校验文件）。
- 不做客户联系（外部联系人）、群机器人 webhook、应用消息模板卡片更新。
- 不做接收消息回调（智能机器人收发由 `agenthub_wecom` 负责，与本模块无关）。
- 撤回遵循企业微信官方限制：仅 24 小时内、仅企业微信客户端推送的消息
  （"微信插件端"收到的消息不支持撤回），本模块不做任何绕过。

## 外部依赖

- Python 包 `wechatpy`（企业微信服务端 API 的 SDK）。
