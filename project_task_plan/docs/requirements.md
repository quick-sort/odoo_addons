# project_task_plan — 需求

## 背景与问题

项目里的任务可以建立依赖关系（Blocked By / Blocks，即核心 `project` 的
`depend_on_ids` / `dependent_ids`）。但这两个字段只影响「阻塞」状态机：前置任务
没完成时后置任务处于 blocked 状态，**日期之间没有任何联动**。

结果是：改了一个前置任务的起止日期，所有依赖它的后置任务都要手动逐个顺延，
容易漏、容易错，也没有一个「例外不自动排」的开关。

## 目标

新增 `project_task_plan` 模块，让有依赖关系的任务在**保存时自动排期**：

- 项目维度可开关（是否自动调整排期）；
- 任务维度可开关（某个任务例外、不参与自动调整）；
- 任务上有一个 **lead time**（提前期，天）字段，控制前置任务结束后到本任务
  开始的最小间隔。

## 范围

- 复用核心 `project` 的依赖关系（`depend_on_ids` / `dependent_ids`），**不新建
  依赖建模**。
- 复用 `project_task_gantt` 的 `task_start_date` / `task_end_date` /
  `gantt_duration` 作为排期的起止/时长字段。
- 排期规则：
  - 后置任务开始 = 所有前置任务结束的最大值 + 本任务 lead time。
  - 保持时长整体平移：后置任务结束 = 新开始 + 原 `gantt_duration`。
  - **双向**：前置提前则后置提前，前置推迟则后置推迟。
  - `lead_time` 必须非负（≥ 0），不允许负数（0 表示紧接前置结束、无间隔）。
  - **忽略已完成任务**：`is_closed`（Done / Cancelled）的任务不参与排期，不被
    自动移动；但它们仍可作为未完成后继的前置约束。
- 开启行为：项目开关开启后显示一个「自动对齐」按钮，点击该按钮对项目内已有
  任务做一次批量排期拉齐，并弹出「调整结果」窗口，列出被调整的任务及新旧
  起止日期。

## 明确不做（边界）

- 不做资源/工作量负载均衡，不做资源日历工作日计算（lead time 按自然天）。
- 不做 Gantt 拖拽时的实时联动（先只做保存时联动，拖拽后续可接）。
- 不做手动排期与自动排期的复杂冲突解决——只有任务级 `no_auto_schedule` 一个
  例外开关，没有「手动/自动」双态字段。
- 不做跨项目依赖的级联移动：一个任务是否被移动只看**它自己**所属项目的开关；
  跨项目的前置任务仍提供结束日作为约束。
- 不引入图库或新第三方依赖。
