==================
InfoHub 摘要推送
==================

按读者在订阅上设置的周期（每日 / 每周）把未读条目汇总成一封邮件发出去。

不做站内通知（ADR-013），对外触达只有这一条渠道。

一封邮件，不是一个订阅一封
==========================

按 **(用户, 周期)** 分组发送：一个用户订阅了 10 个学科，收到的是**一封**汇总邮件，
而不是 10 封。用户同时有每日和每周订阅时，各收一封。

只统计 ``digest_frequency`` 等于该周期的订阅——用户可以把一部分订阅设成「不推送」，
那些内容不会出现在邮件里。

发送记录用于幂等
================

``infohub.digest.log`` 记录每次发送。到期判定是"该 (用户, 周期) 在本周期内还没有
成功发送记录"，而**不是**在用户或订阅上放一个 ``last_digest_at`` 时间戳。

差别在 cron 重跑、多 worker 并发、发送中途失败这几种情况下：日志能给出准确答案，
单个时间戳会漏发或重发。cron 因此是**重跑安全**的，一天跑几次都不会重复发。

三种状态的语义
--------------

=========  ================================================================
状态       含义
=========  ================================================================
``sent``   已发送。算已处理
``skipped``本周期没有未读内容。**也算已处理**——否则每轮 cron 都要为这个用户重算一遍条目
``failed`` 发送失败（无邮箱、邮件服务器拒收等）。**不算已处理**，留给下一轮重试
=========  ================================================================

内容筛选
========

一封摘要包含的条目是：命中订阅 ∧ 已发布 ∧ 本周期内发布 ∧ **未读** ∧ 未被隐藏 ∧
不带屏蔽标签 ∧ 符合语言偏好。portal 用户还会排除 ``access_level = internal`` 的源。

未读判定用 ``not any`` 生成 NOT EXISTS 子查询，不物化已读 ID 列表。

按评分降序排列——评分高的放前面（评分由 ``infohub_filter`` 的规则或
``infohub_llm`` 设置）。单封最多列 30 条，超出显示"共 N 条，以下列出前 30 条"。

正文是可编辑的 QWeb 视图，不是 mail.template
============================================

没有用 ``mail.template``：模板正文需要遍历"该用户该周期的未读条目"，而
``mail.template`` 的渲染上下文只有 ``object``，拿这套动态数据很别扭。

改成渲染 ``ir.ui.view``（``infohub_digest.digest_email``）再建 ``mail.mail``。视图本身
仍然是数据库记录，管理员照样能改，可编辑性没有损失。

邮件客户端的 CSS 支持很差，所以模板一律用**内联 style**，不用 class、不用外部样式表。

依赖说明
========

只依赖 ``infohub``。邮件里的"在网站上查看"和"订阅管理"链接指向 ``/infohub`` 与
``/infohub/subscriptions``，那两个路由由 ``infohub_website`` 提供——没装的话链接会
404，但邮件本身是自足的（条目标题直接链向原文）。实际部署建议两个一起装。
