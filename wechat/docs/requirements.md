# 业务需求

## 背景与动机

外部仓库 `odoo-wechat` 以五个模块覆盖微信生态（base / mp / login / payment /
work）。本仓库按需收敛：先只引入**个人微信公众号**这一条线，把原
`wechat_base`（公共层）与 `wechat_mp`（公众号）合并为单个 addon `wechat`。
企业微信（`wechat_work`）不在范围；扫码登录与支付若将来引入，作为独立
addon 依赖本模块（见「不做」）。

## 要解决的业务问题

1. 微信公众号用户发来的消息需要被接收、留痕，并能按关键字自动回复。
2. 运营需要在 Odoo 内维护公众号自定义菜单并推送到微信。
3. 业务事件（订单、发货、支付成功等）需要通过模板/群发消息触达关注者。
4. 关注者需要在 Odoo 内形成可运营的用户资产（关注状态、标签、分组、统计）。

## 范围内的功能点

| # | 功能 | 说明 |
|---|------|------|
| F1 | 公司级凭证 | 每公司一套 AppID/AppSecret/Token/AESKey，公司表单配置 |
| F2 | Access Token 生命周期 | 缓存、过期刷新、40001/42001 失效重试 |
| F3 | 回调服务器 | URL 验证（GET）+ 消息接收（POST，明文/AES） |
| F4 | 消息留痕 | 全量消息落库，保留天数可配，每日清理 |
| F5 | 关键字自动回复 | 精确/模糊/正则匹配，优先级，6 种回复类型，触发统计 |
| F6 | 默认回复 / 关注回复 | 每公司各一条，被动回复 |
| F7 | 关注/取关用户生命周期 | 关注建档（含二维码场景参数）、取关更新状态 |
| F8 | 自定义菜单 | 结构化编辑 → 微信 JSON → 同步/删除远程菜单 |
| F9 | 模板消息 | 模板注册表 + 发送 + 统计 |
| F10 | 群发消息 | 全量或按标签，状态跟踪，失败重试 |
| F11 | 用户标签/分组 | 本地维护 |
| F12 | JSON-RPC API | 模板发送/用户列表/菜单推送/带参二维码/素材上传 |

## 明确不做

- **企业微信**（`wechat_work`）：不同产品线，不引入。
- **扫码登录 / 微信支付**：本次不合并。将来若需要，做成依赖 `wechat`
  的独立 addon，复用 `wechat.request` 与公司凭证字段——而不是塞回本模块。
- **客服消息、数据统计、广告**等高级公众号能力。
- **多公众号 per 公司**：一家公司一个公众号（公司级唯一约束）。
- **主动消息推送引擎**（定时任务）:群发的 `scheduled_date` 仅存计划值，
  不实现定时投递。

## 用户与场景

- 运营人员：维护菜单、关键字规则、群发（Odoo 后台）。
- 关注者：与公众号交互（微信客户端，被动方）。
- 外部集成方：通过 JSON-RPC 触发模板消息等（Odoo 用户凭证）。
